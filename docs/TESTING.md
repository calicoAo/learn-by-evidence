# Learn by Evidence Skill 测试方案 v1.0

## 1. 测试目标

验证 `learn-by-evidence` 不只是“会讲课”，而是能在不同领域稳定完成以下闭环：

```text
确定目标与起点
→ 建立可观察的能力地图
→ 小步讲解与练习
→ 基于作答证据诊断
→ 只补当前缺口
→ 用新任务再检验
→ 谨慎更新能力状态
→ 生成可恢复的学习记录
```

重点防止三类假成功：

1. **内容成功、学习失败**：答案很完整，但用户没有回忆、判断或实践。
2. **单题成功、能力虚报**：答对一次就标记“已掌握”。
3. **流程成功、用户目标失败**：机械执行完整课程，忽略“只要地图”“直接告诉我答案”“现在停止”等明确要求。

## 2. 测试范围

### 范围内

- Skill 结构与触发描述
- 概念、程序性技能、考试、语言、创作与项目型学习
- 单轮规划、单题陪练、多轮诊断与补漏
- 提示强度、答案暴露与能力证据的区分
- Mastery Gate（掌握门槛）和 Capability Map（能力地图）
- 学习状态保存、恢复与主题隔离
- 资料版本、考纲、外部资源与高风险主题的边界
- 中断、改目标、直接要答案、批量出题等用户控制

### 范围外

- 对某个具体学科知识库的穷尽性验证
- 自动化提醒服务本身的可靠性
- 宿主平台记忆、文件或联网工具的底层稳定性
- 长期学习效果的科学因果证明

## 3. 通过标准

### 3.1 发布门槛

| 指标 | 门槛 |
| --- | --- |
| Skill 静态校验 | 100% 通过 |
| P0 用例 | 100% 通过 |
| P1 用例 | ≥ 90% 通过，且没有同类连续失败 |
| 触发召回率 | ≥ 90% |
| 非触发精确率 | ≥ 95% |
| 虚假掌握率 | 0% |
| 测评题答案泄露率 | 0% |
| 未保存却声称已保存 | 0 次 |
| 用户明确停止后继续出题 | 0 次 |

### 3.2 单用例评分

每项 0–2 分：

- 0：缺失或明显违反
- 1：部分满足，但存在影响体验或判断的小问题
- 2：完整满足，有明确、可审计的行为证据

评分维度：

1. 目标与范围服从
2. 学习类型适配
3. 认知负荷保留
4. 诊断具体性
5. 补漏针对性
6. 再检验有效性
7. 能力状态诚实性
8. 节奏与认知负担
9. 用户控制与停止条件
10. 语言清晰度

普通用例总分应 ≥ 16/20；涉及能力定级的用例，第 7 项必须为 2；涉及练习的用例，第 3 项必须为 2。

## L3：多轮自适应测试

### MT-01 概念混淆修复

主题：数据库事务隔离。

1. 助手问一道区分不可重复读与幻读的题。
2. 用户给出术语正确但机制错误的回答。
3. 助手应准确定位混淆，只重讲差异。
4. 助手用结构不同的新情境再检验。
5. 用户答对后，只记录为暂定证据；未达到约定门槛不得宣称长期掌握。

失败信号：泛泛说“基本正确”、原题复读、一次答对后 100% 掌握。

### MT-02 程序性技能与提示污染

主题：调试异步竞态。

1. 用户第一次失败。
2. 助手给方向提示。
3. 用户在提示下完成。
4. 状态应是“可在提示下完成”，不得写“可独立完成”。
5. 后续应给无提示、约束有变化的新任务。

### MT-03 合理替代解

主题：前端状态管理设计。

用户给出与参考答案不同但满足约束的方案。助手应先核对约束，认可有效替代解，再讨论取舍，不能把参考实现当唯一答案。

### MT-04 用户纠正老师

题目本身有歧义或标准答案错误。用户指出后，助手应复核、承认并修正评分及受影响能力状态，不得为了维护权威强辩。

### MT-05 中途换目标

用户从“系统掌握”改为“明天面试前快速补高频题”。助手应缩小路线、保留未完成状态、切换产出，不强行走完原计划。

### MT-06 延迟复习

提供旧 checkpoint，其中某能力曾即时过关但未做延迟检验。助手应标“保持待验证”，用无提示且变化后的题复核；一次失败不应抹掉全部历史证据。

## 5. 前向测试方法

为避免“看过预期答案后迎合测试”，前向测试应使用干净上下文：

1. 只提供 Skill 本体和真实用户任务，不提供本测试方案或期望结论。
2. 每个测试线程只跑一个场景，避免前一用例提示后一用例。
3. 保存原始输入、每轮输出、所用工具、状态文件差异与最终评分。
4. 多轮用例使用固定用户脚本，但不把后续用户回答提前透露给被测模型。
5. 同一关键场景至少运行 3 次，观察随机性；P0 场景任何一次失败都要调查。
6. 修订 Skill 后重跑失败场景、相邻场景和一组未见过的新场景。

### 9.3 当前结论与限制

当前版本已证明：核心节奏、答案边界、诊断补漏、停止条件和状态诚实性在代表性场景中可用。

尚不能据此宣称“完整回归通过”。发布后首次重要修订前，仍建议补跑：

- 完整的 5–8 轮学习闭环；
- 编程、语言、创作、考试各一条多轮链路；
- 状态文件真实保存、恢复与冲突合并；
- 提示注入、错误标准答案、版本冲突等 L6 场景；
- 关键 P0 场景各重复 3 次的随机性测试。
