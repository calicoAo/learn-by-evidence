# Architecture

## 设计目标

Learn by Evidence 把 AI 的职责限制在路径设计、讲解、反馈、诊断和状态压缩，把真正形成能力所需的回忆、判断、首次实践和迁移留给学习者。

## 三层结构

### 1. 触发层

`SKILL.md` frontmatter 的 `description` 同时说明：

- Skill 能完成什么；
- 哪些用户请求应该触发；
- 哪些普通事实问答、翻译、摘要和直接代做不应被强制改造成课程。

### 2. 核心工作流层

`SKILL.md` 保留每次触发都需要的规则：

```text
确定范围
→ 建立能力地图
→ 诊断/讲解/练习
→ 反馈与补漏
→ 新任务再检验
→ 掌握门槛
→ 状态更新与收束
```

默认采用单题节奏，但显式允许用户切换到批量题、直接答案、只要地图或立即停止。

### 3. 按需参考层

- `references/domain-adaptation.md`：不同领域的讲解锚点、代表产出、迁移方式和常见误判。
- `references/explanation-protocol.md`：先测后讲、锚点复用、信息预算、支架撤除与输出删减。
- `references/state-and-review.md`：状态字段、证据更新、复习选择与换窗交接。

只有对应任务发生时才读取参考文件，避免每次触发都占用上下文。

## 证据模型

能力状态由两个维度组成：

| 维度 | 作用 |
| --- | --- |
| `level` | 表达当前表现：理解、提示下完成、独立完成、解释与迁移 |
| `verification` | 表达证据可靠度：未验证、暂定、已验证、待复核 |

另用 `retention` 表达长期保持是否经过延迟检验。这样可以区分：

- 刚刚答对一次；
- 多种任务下稳定完成；
- 过一段时间仍能无提示完成。

## 关键不变量

1. 讲过不等于理解。
2. 看过答案后复述不等于独立完成。
3. 同一题重复不构成多条独立证据。
4. 覆盖率不等于掌握率。
5. 保存、测试、提醒和联网核验只有实际成功后才能声称完成。
6. 用户本轮明确指令高于 Skill 默认节奏。

## 状态机

```text
ASSESS → PLAN → TEACH → PRACTICE → FEEDBACK
                    ↑                    ↓
                    └──── REPAIR ← DIAGNOSE
                                      ↓
                                MASTERY_CHECK
                                  ↙       ↘
                              REPAIR     CLOSE/REVIEW
```

这不是必须逐步展示给用户的 UI 流程，而是内部行为约束。窄任务可以只经过其中一部分。

## 测试架构

- 静态层：frontmatter、引用、元数据、占位内容。
- 触发层：应该触发与不应触发的请求。
- 行为层：单题、提示、直接答案、停止条件。
- 讲解层：锚点选择、信息密度、篇幅护栏、表示切换与压缩一致性。
- 多轮层：误解诊断、补漏、迁移和能力更新。
- 状态层：保存、恢复、冲突、答案暴露与主题隔离。
- 鲁棒性层：提示注入、错误标准答案、版本冲突与高风险领域。

静态脚本只能验证包结构；教学效果必须通过真实模型前向测试验证。
